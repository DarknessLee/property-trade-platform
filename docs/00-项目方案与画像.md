## 2. 角色与权限域（初稿，M1 冻结矩阵）

| 角色 | 端 | 主要权限域 |
| --- | --- | --- |
| 买方 buyer | C 端门户 | 浏览/搜索房源、预约带看、咨询留言、查看本人合同与交易进度 |
| 卖方 seller | C 端门户 | 委托房源、查看意向客户统计、确认带看、查看本人合同与进度 |
| 经纪人 agent | B 端工作台 | 房源录入/维护/上下架、客户档案、带看安排与反馈、发起签约 |
| 店长 store_manager | B 端工作台 | 门店房源/客户/经纪人管理、审批（调价/钥匙委托）、业绩看板 |
| 财务 finance | B 端工作台 | 佣金/业绩核对、交易款项记录（Mock） |
| 平台管理员 admin | B 端后台 | 房源验真审核、身份审核、机构资质、数据字典、操作日志 |

原则：前端隐藏 + 后端兜底；每个角色至少 1 条允许 + 1 条拒绝用例。

## 3. MVP 业务闭环

- **C 端**：找房（筛选/详情/地图）→ 注册实名 → 预约带看/在线咨询 → 查看合同 → 交易进度时间轴。
- **B 端**：房源录入 → 验真审核 → 客户建档/标签 → 带看日程/反馈/评级 → 合同模板选择/在线签署 → 交易进度维护 → 门店业绩统计。

## 4. 数据模型（方案 §3.4 摘录）

User、Customer、HouseListing、Community、Showing、Contract、TransactionProgress、Agency、Agent + 附加：ContractTemplate、Notification、OperationLog、DataDict、RealNameAuth（实名）。
所有业务表带 `created_at`、`updated_at`、`is_deleted`，软删除。

## 5. 技术边界（Demo 诚实声明）

- 电子签为本地 Mock：签名图、合同编号、回调事件均本地生成，**不具备法律效力**。
- 支付、短信、实名认证、地图为 Mock/占位实现，不申请真实第三方密钥。
- 房源图片使用本地占位图/生成图，不接 OSS/CDN。
- 单机开发环境运行，不承诺方案 §2.2 的并发/可用性指标；PLAN-MATRIX 标注为「不做（Demo 边界）」。
